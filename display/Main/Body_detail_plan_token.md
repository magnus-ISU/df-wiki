### Tokens

<table>
<tbody><tr>
<th>Token
</th>
<th>Arguments
</th>
<th>Description
</th></tr>
<tr>
<td> <a href="#body-detail-plan">BODY_DETAIL_PLAN</a>
</td>
<td>
<ul><li>identifier</li></ul>
</td>
<td>Create a new body detail plan with the specified identifier.  The rest of the tokens in this table are then used to define this body detail plan's properties.
</td></tr>
<tr>
<td> <a href="#add-material">ADD_MATERIAL</a>
</td>
<td>
<ul><li>identifier</li>
<li>material template</li></ul>
</td>
<td>Adds a new material to the creature based on the specified template and assigned to the specified identifier.
</td></tr>
<tr>
<td> <a href="#add-tissue">ADD_TISSUE</a>
</td>
<td>
<ul><li>identifier</li>
<li>tissue template</li></ul>
</td>
<td>Adds a new tissue to the creature based on the specified template and assigned to the specified identifier.
</td></tr>
<tr>
<td> <a href="#bp-layers">BP_LAYERS</a>
</td>
<td>
<ul><li><a href="Body_token.md#category">BY_CATEGORY</a> or <a href="Body_token.md#contype">BY_TYPE</a> or <a href="Body_token.md#bp">BY_TOKEN</a></li>
<li>body part</li>
<li>tissue name or tissue ARG# for innermost tissue</li>
<li>tissue thickness</li>
<li>tissue name or tissue ARG# for second innermost tissue</li>
<li>tissue thickness</li>
<li>tissue name or tissue ARG# for third innermost tissue</li>
<li>tissue thickness</li></ul>
<p>etc...
</p>
</td>
<td>Defines a series of tissue layers. Alternatively to specifying a tissue, variable arguments can be entered (numbered arbitrarily to a max of 5) to be filled with tissues when the plan is called in the creature entry. The SELECT_TISSUE creature token with TL_RELATIVE_THICKNESS can change tissue thickness, but tissue <i>layering</i> is hard to do without a new detail plan.
</td></tr>
<tr>
<td> <a href="#bp-layers-over">BP_LAYERS_OVER</a>
</td>
<td>
</td>
<td>Works like BP_LAYERS, but defines layers over existing layers.
</td></tr>
<tr>
<td> <a href="#bp-layers-under">BP_LAYERS_UNDER</a>
</td>
<td>
</td>
<td>Works like BP_LAYERS, but defines layers under existing layers.
</td></tr>
<tr>
<td> <a href="#bp-position">BP_POSITION</a>
</td>
<td>
<ul><li>BY_CATEGORY or BY_TYPE or BY_TOKEN</li>
<li>body part</li>
<li>position token</li></ul>
</td>
<td>Defines a position for the specified body part relative to its parent part (the nose is assigned the position FRONT, as it's on the front of the face). This has some effects on combat, attacks and the like. Valid position tokens are FRONT, BACK, LEFT, RIGHT, TOP and BOTTOM. The position token SIDES is of unverified validity.
</td></tr>
<tr>
<td> <a href="#bp-relation">BP_RELATION</a>
</td>
<td>
<ul><li>BY_CATEGORY or BY_TYPE or BY_TOKEN</li>
<li>body part to be affected</li>
<li>relation token</li>
<li>BY_CATEGORY or BY_TYPE or BY_TOKEN</li>
<li>parent body part</li>
<li>coverage</li></ul>
</td>
<td>Defines a positional relationship between one body part and another (the right eyelid is AROUND the right eye with coverage 50, as it only partially covers the eye). This has some effects on combat, attacks and the like. Valid relation tokens are AROUND, SURROUNDED_BY, ABOVE, BELOW, IN_FRONT, BEHIND, CLEANS, and CLEANED_BY. The lattermost two tokens are used when specifying parts that clean each other (such as eyelids to eyes).
</td></tr>
<tr>
<td> <a href="#bp-relsize">BP_RELSIZE</a>
</td>
<td>
<ul><li>BY_CATEGORY (or, presumably, BY_TYPE or BY_TOKEN)</li>
<li>body part</li>
<li>relsize</li></ul>
</td>
<td>Defines a relsize for the selected body part for the current body detail plan
</td></tr></tbody></table>
